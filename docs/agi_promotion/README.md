# 让两台服务器 AGI 在互联网上推广 SASES

## 目标

用两台独立服务器上的 AGI 节点，分别覆盖国内与海外受众，
在不依赖外部远程桌面的情况下，完成一次可观察、可回执、可审计的推广实验。

## 节点

| 角色 | 位置 | 节点 | 覆盖 |
|---|---|---|---|
| 国内 | 杭州 | node-C | 中文 / 国内受众 |
| 海外 | 香港 | node-B | English / international audience |

## 当前状态

- 杭州：SASES 已启动，`schema_version=18`，`node_id=node-C`
- 香港：SASES 已启动，`schema_version=18`，`node_id=node-B`
- 两端都已存在模型 API Key
- 代码已同步到统一版本，保留原有 `users.db` 与 `.env`

## 实验原则

1. 两个节点独立决策，不共享同一份推广文案。
2. 国内节点输出中文内容，海外节点输出英文内容。
3. 先生成、后审核、再发布，不自动外发。
4. 每次推广产生 `campaign_id`、`region`、`published_at` 和回执。
5. 失败可重试，重复 `campaign_id` 幂等。

## 推广流程

```text
区域 AGI 生成内容
→ 本地审核
→ 生成 campaign_id
→ 发布到对应区域
→ 返回 receipt
→ 汇总阅读/点击/错误
```

## 预期结果

- 两个区域都能独立完成内容生成与发布
- 国内/海外内容语言、时区、渠道不同
- 每条推广都有回执与审计
- 单节点失败不影响另一节点

## 后续

- 接入真实发布渠道前，先做 7 天沙盒
- 增加内容审批与频率限制
- 对海外内容做本地化审校
- 保留可回滚的发布记录

> 说明：这是一次受控测试，不包含自动批量外发、刷量或规避平台规则的行为。
