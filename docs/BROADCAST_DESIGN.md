# 广播系统设计文档

版本：v1.0（2026-10-10）
状态：设计阶段，未实现

## 一、广播的定位

广播不是"消息推送"，是"事件分发系统"。

它涉及十个维度：一致性、持久性、顺序、安全、审计、优先级、离线、加密、组播、回执。

SASES 当前只做了最基础的一层（同进程 WS 广播）。

## 二、广播的三层分级

### L1：进程内广播（已实现）

场景：单节点多窗口、单设备多账号
- WS 连接池内所有客户端
- 无网络开销
- 现有实现：ws_routes.broadcast_to_user / broadcast_to_group

### L2：节点间广播（待实现）

场景：主节点 → 副本、跨服务器
- 8001 ↔ 8002 ↔ 8003
- 需要"节点间通道"
- 上服务器时新增

### L3：用户级广播（待实现）

场景：用户手机 ↔ 电脑
- 通过 L2 中继 + 用户级寻址
- 蜂巢终局

## 三、跨节点广播的实现方案

### 方案 A：HTTP 轮询

副本每 2 秒问主节点"有新消息吗"
- 简单
- 延迟 2 秒

### 方案 B：WS 长连接（推荐）

副本主动连主节点的 `/ws/hive/broadcast`
- 实时
- 需要重连机制

### 方案 C：消息队列

引入 Redis/RabbitMQ 做中转
- 生产级
- 需额外服务

## 四、多账号 + 节点 + 广播的关系

### 蜂巢层（底层协议）

物理设备 = 1 个节点
- 节点 ID = 设备的 Ed25519 公钥
- 节点持有：1 个或多个账号的密钥

### 智维空间（用户界面）

显示时按"账号"展开
- 账号 X 的节点
- 账号 Y 的节点
- 但底层指向同一个蜂巢节点

### 广播路由

- 账号级广播（L1）：同节点内直接
- 节点级广播（L2）：跨节点
- 用户级广播（L3）：跨设备

**关键：广播按"账号"寻址，路由按"节点"分发——两个维度正交，不冲突。**
