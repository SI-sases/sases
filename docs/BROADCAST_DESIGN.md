# 广播系统设计文档

版本：v1.0（2026-10-10）
状态：设计阶段，未实现

## 一、广播的定位

广播不是"消息推送"，是"事件分发系统"。

它涉及十个维度：一致性、持久性、顺序、安全、审计、优先级、离线、加密、组播、回执。

SASES 当前只做了最基础的一层（同进程 WS 广播）。

## 二、广播的三层分级

### L1：进程内广播（已实现）

场景：单节点多窗口、单设备多账号
- WS 连接池内所有客户端
- 无网络开销
- 现有实现：ws_routes.broadcast_to_user / broadcast_to_group

### L2：节点间广播（待实现）

场景：主节点 → 副本、跨服务器
- 8001 ↔ 8002 ↔ 8003
- 需要"节点间通道"
- 上服务器时新增

### L3：用户级广播（待实现）

场景：用户手机 ↔ 电脑
- 通过 L2 中继 + 用户级寻址
- 蜂巢终局

## 三、跨节点广播的实现方案

### 方案 A：HTTP 轮询

副本每 2 秒问主节点"有新消息吗"
- 简单
- 延迟 2 秒

### 方案 B：WS 长连接（推荐）

副本主动连主节点的 `/ws/hive/broadcast`
- 实时
- 需要重连机制

### 方案 C：消息队列

引入 Redis/RabbitMQ 做中转
- 生产级
- 需额外服务

## 四、多账号 + 节点 + 广播的关系

### 蜂巢层（底层协议）

物理设备 = 1 个节点
- 节点 ID = 设备的 Ed25519 公钥
- 节点持有：1 个或多个账号的密钥

### 智维空间（用户界面）

显示时按"账号"展开
- 账号 X 的节点
- 账号 Y 的节点
- 但底层指向同一个蜂巢节点

### 广播路由

- 账号级广播（L1）：同节点内直接
- 节点级广播（L2）：跨节点
- 用户级广播（L3）：跨设备

**关键：广播按"账号"寻址，路由按"节点"分发——两个维度正交，不冲突。**


## 五、十个维度详解

### 维度 1：持久性

**问题**：广播纯内存，节点掉了消息丢。

**分类**：
- 瞬时广播（光标、正在输入）：不落库
- 持久广播（消息、转账）：落库 + 拉取补偿

### 维度 2：顺序

**问题**：不同节点收到顺序可能不同。

**分级**：
- 单聊：不需要（只有两人）
- 群聊：需要（按服务端时间戳）
- 积分转账：必须

**已有基础**：logical_clock 字段（B0 预留）

### 维度 3：幂等

**问题**：同一条广播收到两次。

**方案**：
- 广播带 message_id（已有 global_msg_id）
- 客户端 _seenIds Set 去重
- 服务端给广播加去重表

### 维度 4：广播风暴

**问题**：1000 节点，每个广播 1 次/秒 = 999,000 次/秒。

**方案**：
- 分层广播（小中枢→大中枢）
- Gossip 协议（随机 3-5 邻居）
- Pub/Sub 消息队列

蜂巢 3 层架构天然适合分层广播。

### 维度 5：实时性配置

**用户级配置**：
- realtime（立即推送）
- batched（5 分钟批量）
- silent（静默，打开时拉取）

当前：所有用户都是 realtime。
