## 二、DSH 会怎么做

DSH 不会从零写视频编辑器或 Windows CUA。

### P3 视频剪辑

DSH 会：

```text
检查已安装的 MCP / CLI / 工具
有 FFmpeg → 用 job spec 调用
有 MCP → 挂 MCP
没有 → 明确 blocked
```

预计：3–6 步。

### P4 桌面

DSH 会：

```text
检查已挂载的 CUA provider / Windows-MCP
有 → 配置一个 cua 入口
没有 → 明确 blocked，不从零写原生驱动
```

预计：3–6 步。

### P5 API 注册

DSH 会：

```text
grep 是否全量注入
没有 → 0 代码改动
有 → 改检索
```

预计：2–4 步。

SASES 的 30 步不是“能力不行”，是**任务定义失败**：

```text
没有定义每个阶段的停止条件
没有要求最小交付物
允许无限审计
```

## 三、减法决定

### P5：直接关闭

SASES 已证明：

```text
FROM api_registry 查询 0 命中
prompt/context 无 registry 数据源
```

结论：

```text
P5 不需要开发
从计划中删除
```

### P3：不从零做编辑器

只允许：

```text
video_edit 适配器
底层：FFmpeg / MCP / 项目 JSON
```

如果没有 FFmpeg/MCP：

```text
blocked，不写假实现
```

### P4：不从零做 CUA

只允许：

```text
复用 Windows-MCP / MCP / DSH CUA provider
一个 cua 入口
```

没有 provider：

```text
blocked，不写原生驱动
```

## 四、重写后的任务卡

### P3 任务卡

```text
目标：判断 video_edit 能否落地
预算：5 步

1. 检查 ffmpeg/ffprobe 是否存在
2. 检查是否有可用 MCP/CLI
3. 有：给一个最小 video_edit manifest + 调用示例
4. 没有：输出 blocked，不写实现
5. 只输出结论，不审计无关代码
```

### P4 任务卡

```text
目标：判断 cua 能否复用现成 provider
预算：5 步

1. 检查 Windows-MCP / MCP / DSH CUA 是否可用
2. 有：给一个 cua 入口设计 + 最小调用
3. 没有：输出 blocked，不写原生驱动
4. 不新增动作工具
```

### P5 任务卡

```text
已关闭：无全量注入，无需开发
```

## 五、SASES 执行规则修正

```text
一个任务只做一个阶段
每个阶段必须有最小交付物
没有依赖就 blocked，不允许用 30 步审计代替结论
总步数预算 5–8
超过预算返回失败，不谎报完成
```
