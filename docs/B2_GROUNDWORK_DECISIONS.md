# B2 地基决策文档

## 决策 1：HLC 格式
格式：{13位毫秒}.{6位补零}.{4位节点ID}
示例：1697000000000.000042.n001
理由：定长补零保证字符串排序等于数值排序
影响范围：所有含 hlc_ts 字段的表

## 决策 2：节点 ID 格式
格式：n001 / n002 / n000
理由：4 位定长，n000 保留给未知来源
影响范围：node_registry 表新增 hlc_prefix 字段

## 决策 3：一致性承诺
承诺：2-5 秒最终一致，写己之写立即可读
理由：符合人类感知阈值，符合局域网物理极限
影响范围：用户协议 + 前端状态提示

## 决策 4：分片策略
策略：先全量副本，所有表加 shard_key 字段预留
理由：当前数据量小，分片复杂度高
影响范围：所有业务表加 shard_key TEXT DEFAULT ''

## 决策 5：回填策略
策略：存量 hlc_ts = created_at 转换，origin_node = 'n000'
理由：保留时间序，便于未来冲突检测
影响范围：迁移脚本的回填逻辑

## 决策 6：冲突表策略
策略：只写不读，30 天清理，不弹窗
理由：用户不需要知道 CAS 冲突
影响范围：conflicts 表 + 清理任务

## 决策 7：开关
配置项：CONFLICT_DETECTION_ENABLED = true / false
理由：出问题时可秒级降级
影响范围：冲突检测逻辑
